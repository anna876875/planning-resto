# Instructions pour le développement du SaaS "Planning Restauration"

## 🌐 Contexte Métier (Restauration)
Ce SaaS génère et optimise des plannings de travail pour des restaurants, brasseries et bars.
Les règles métier critiques à TOUJOURS respecter dans le code :
1. **Droit du travail & Convention collective HCR (Hôtellerie-Restauration)** :
   - Temps de repos minimum entre 2 shifts : 11 heures consécutives.
   - Durée maximale de travail quotidien : 10h (extensible à 12h sous conditions).
   - Pauses obligatoires : 20 min toutes les 6h de travail.
   - Gestion des coupures (ex: service midi 11h-15h + service soir 18h-23h).
2. **Rôles & Compétences (Skills)** :
   - Rôles principaux : Salle (Serveur, Chef de rang, Runner), Cuisine (Chef, Second, Plongeur), Bar, Manager.
   - Un planning doit garantir un quota d'expérience minimal par service (ex: au moins 1 manager ou 1 chef de rang présent).
3. **Optimisation des coûts** :
   - Suivi en temps réel du ratio Masse Salariale / Chiffre d'Affaires prévisionnel.

## 🛠 Stack Technique
- **Frontend** : Next.js 14+ (App Router), TailwindCSS, Shadcn/ui.
- **Backend/Database** : Supabase (PostgreSQL, Row Level Security, Auth).
- **Moteur d'Optimisation / IA** : Python (FastAPI + OR-Tools) OU TypeScript (Constraint Solver).
- **Gestion des dates** : `date-fns` ou `Day.js` (toujours gérer les timezones en UTC dans la DB).

## 📐 Directives de Code
- Utiliser uniquement du TypeScript strict.
- Séparer la logique d'optimisation (moteur de contraintes) de la couche d'interface.
- Modulariser la validation des plannings (créer un moteur d'audit de conformité légale).
- Écrire des tests unitaires pour chaque règle légale HCR.
